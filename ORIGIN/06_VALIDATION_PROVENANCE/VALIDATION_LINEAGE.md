# VALIDATION / PROVENANCE LINEAGE

## Determinism
Historical specs require deterministic execution for a fixed canonical input, runtime policy and research profile.

## Forward-only
New observations become evidence for subsequent ticks. They do not rewrite already established Core State.

## Traceability
The runtime lineage should be traceable as:

`raw input -> canonical state -> graph/topology -> weights/field -> dynamics -> emergence/output -> evidence`

## Canonical serialization
The merged runtime lineage uses canonical JSON with sorted keys and SHA-256 provenance. Precision must be explicit and research values must carry calibration status.

## Regression requirements
Historical regression checklists identify preservation of S00–S08, DWL, DPKE, BEC density/observation separation, no feedback loop, risk-to-source traceability, spacetime contracts, evidence chains, forecast windows/uncertainty, actor/action mapping, deterministic JSON/hash, and dimension/version/constants/test vectors for matrices.

## v3.4 validation boundary
For the current anchor, tests must separately verify:
- Entity identity does not become an essence label;
- spatial `B(V_k)` is attached to Space, not Entity;
- `event_count`, `cycle_count`, `K_rep` are independent;
- rhythm is calculated from relation/event sequence;
- ISO 8601 parsing is timezone-safe;
- tie-breaking is deterministic;
- absent L4 state does not generate fabricated S07 values;
- quantitative and qualitative outputs remain traceable to evidence.

## Provenance principle
When historical sources disagree, record the disagreement and source/version instead of silently blending formulas.
